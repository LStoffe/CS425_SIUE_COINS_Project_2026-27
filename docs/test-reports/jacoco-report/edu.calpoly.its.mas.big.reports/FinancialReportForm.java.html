/**
 * Holds info on job costs and job income.
 * <br><br>
 * This class is updated for BIGv3 to serve a slightly different purpose than it did in BIGv2.
 * In BIG v2 this represented the one and only financial report and financial info
 * went from this class directly into the GUI.  In BIGv3 some fields are removed and this class now
 * holds the underlying data for presenting the job cost reports, payments report and income statement.  The reason
 * for this architecture is because the fields needed for these reports were already handled by <code>
 * FinancialReportForm</code>.  Reports using data already handled by the <code>FinancialReportForm</code>
 * should be wrapper classes that take the data they need from this class.
 * <br><br>
 * All text below is originally from the BIGv2 version of <code>FinancialReportForm</code>
 * so the reference to jsps are no longer true, however the discussion of <code>JobFinancialInfo</code> objects is
 * still true.
 * <br><br><i>
 * Financial data about particular jobs of a company is stored in an internal list of <code>JobFinancialInfo</code>
 * objects.  These objects are accessible direcly from the <code>getJobInfoList</code> method but <code>FinancialReportForm</code>
 * also provides a primitive interface for manipulating them.  There are set, get and increase methods for job specific data
 * that work like the ones for company data except that they will take a <code>Job</code> object as a parameter.  The method will manipulate the
 * data for that specific job only.  Any <code>Job</code> object used as a parameter in a method call will become part of this
 * Financial Report and be added to the internal list (even from a call to a get method).
 * <br>
 * To simplify displaying job specific data to users the <code>FinancialReportForm</code> offers get methods that will not take a <code>Job</code>
 * as a parameter but will apply to the current job.  The current job can be controlled by the <code>nextJob()</code> method.  Each time <code>nextJob()</code>
 * is called the current job will become the next job in the internal list (if there are still jobs remaining).  There is no way to reset the current
 * job to a different place in the list because it is intended that the jsp will go through the job list once to display each job's info, then
 * have no further use for the list of jobs. </i>
 *
 * @author Kevin Craig
 * @version BIGv3
 */

  //Methods that control the current job info

  /**
   * Returns true if there are jobs left in the list, false o/w.
   */
  public boolean jobsLeft()
  {
	  if ((jobInfoList != null) && (currentJobInfo+1 < jobInfoList.size()))
	  {
		  return true;
	  }
	  else
	  {
		  return false;
	  }
  }

  /**
   * Advances the current job to the next job in this list.
   * <br>Caution: ArrayOutOfBoundException will be thrown if a get method is called on
   * and <code>nextJob</code> was called when there were no jobs left.  Use the <code>jobsLeft</code>
   * to check if there are jobs remaining before calling this method.
   */
  public void nextJob()
  {
	  currentJobInfo++;
  }


  //Returns the JobFinancialInfo object associated with jobid.  If one doesn't exist one is created.
  private JobFinancialInfo getJobInfo(Job job)
  {
	  JobFinancialInfo jobInfo = null;

	  Iterator i = jobInfoList.iterator();
	  while(i.hasNext())
	  {
		  JobFinancialInfo jfi = (JobFinancialInfo) i.next();
		  if (jfi.getJobID() == job.getJobID())
		  {
			  jobInfo = jfi;
		  }
	  }

	  if( jobInfo == null)
	  {
	      jobInfo = new JobFinancialInfo(job);
	      jobInfoList.add(jobInfo);
	      //System.out.println("added jobinfo to list.  Size of list is: " + jobInfoList.size());
	  }

	  return jobInfo;

  }
